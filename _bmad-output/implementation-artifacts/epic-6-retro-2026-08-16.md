## Findings

### 1. FR-11/AD-7's tier-first cascade has no colony-wide or proportional cap — the root cause

`selectJob` (`src/control/match.ts`) orders eligible Jobs strictly by **tier → within-tier priority → distance** (`TIER_RANK`: critical=0 < high=1 < medium=2 < low=3). A Job's own `maxWorkers` caps *that Job instance*, but nothing caps a *Job type* colony-wide. `produceFill` (`src/world/producers/fill.ts`) emits one Job per open spawn/extension, each carrying `JOB_POLICY_TABLE.fill` (`src/config.ts:110-118`, tier `critical`). Total fill capacity is therefore `maxWorkers × count-of-open-fill-targets` — and that target count *grows with RCL*, exactly when build (`medium`, FR-24 container-first) most needs attention. Because `critical` always outranks `medium`/`low` regardless of remaining need elsewhere, fill can — and did — absorb the entire idle population before build or upgrade ever see a Creep.

**Disposition:** fix now, superseded by the pivot (see Action Items). **Source:** `src/config.ts:110-143`, `src/control/match.ts` (`selectJob`, `TIER_RANK`), `src/world/producers/fill.ts`, `src/world/producers/build.ts`; FR-11/AD-7 (`epics.md:26,65`).

### 2. This is not a hypothetical — it directly contradicts SM-1, the MVP's own declared exit criterion

PRD §7: **SM-1 — MVP exit, unattended.** *"From a fresh room to a fully-Specialist colony with the operator acting only to place Container sites once. Validates FR-23–FR-30, NFR-3."* (`prd.md:428`). Specialist activation (FR-26) requires the Evolution trigger (FR-23: RCL≥2 AND 5 Extensions AND Container-per-Source) to fire, which requires Container-first construction (FR-24) to actually complete. Live-observed this session: **10 of 11 creeps on `fill`, 1 on `upgrade`, 0 on `build`, while 5 extensions and 2 containers sat as unbuilt construction sites.** This is SM-1's failure mode, observed live on PTR, not a corner case found by inspection.

**Disposition:** this is why the MVP verdict below is rejected, not merely "one open finding." **Source:** user report, this session; `prd.md:428`; Finding 1's code trace.

### 3. Verification gap: no test at any level modeled colony-wide job-type distribution

`test/control/match.test.ts` has 12 `selectJob` tests and 8 `match()` tests (`describe` blocks at lines 114, 228). Every one is single-pair or small-N scoped: "critical beats nearer medium," "container beats ordinary site when nearer," "exactly one of three Creeps claims a `maxWorkers:1` Job." Story 3.4's AC ("within-tier beats distance") and Story 6.3's AC ("container site beats a nearer ordinary site") are each true in isolation and each tested — and they compose into starvation once fill's *total* open capacity across all its targets exceeds `population − build/upgrade demand`. No story AC and no test ever modeled "N fill targets + M build targets + population P" together. This is the retrospective's own thesis (no single session saw the whole) applied to emergent behavior instead of file size.

**Disposition:** process lesson for Stage 2's test strategy. **Source:** `test/control/match.test.ts:114-227`.

### 4. `fill.maxWorkers` live value (6) is an accepted, documented deviation that multiplies but doesn't cause the starvation

`src/config.ts:114` sets `fill.maxWorkers: 6`; the original spec-pinned value was `1` (`2-3-producers-policy-table.md`). This was a deliberate operator PTR tuning change, documented as a known deviation in `spec-5-1-population-maintenance-spawncreep-issuer.md:133`. The starvation dynamic exists structurally even at `maxWorkers: 1` once extension count scales (5 fill targets × 1 = 5 critical-tier slots, still enough to starve a small population) — the live value of 6 accelerates and worsens an already-present structural gap rather than creating a new one.

**Disposition:** accept as-is; moot once Stage 2 replaces flat per-Job `maxWorkers` with colony-wide pool caps. **Source:** `src/config.ts:114`; `2-3-producers-policy-table.md`; `spec-5-1-population-maintenance-spawncreep-issuer.md:133`.

### 5. AD-5's binary Era is structurally incompatible with the user's "specialist-lite" goal

`deriveEra` (`src/world/snapshot.ts`) returns `"generalist" | "specialist"` — Specialist requires *all* of RCL≥2, all 5 Extensions, and full Container coverage simultaneously (AD-5, `epics.md:63`; FR-23, `epics.md:38`). There is no intermediate state. The user's explicit ask — *"get a specialist up with the first container instead of waiting for all structures to be built, even if it is a nerfed specialist"* — is impossible under this design as specified. This is not a bug; it's a designed constraint the pivot intends to replace with a graduated stage ladder.

**Disposition:** spec reconciliation, superseded by the pivot. **Source:** `src/world/snapshot.ts` (`deriveEra`), `ARCHITECTURE-SPINE.md` AD-5.

- **AD-3 (per-Tick Board regen), FR-13 (claim lock), AD-8 (movement choke point), FR-17 (spawn priority ordering)** all shipped, are all still functioning as designed, and are untouched by the failure above — the defect is specifically in the matching/policy layer's lack of proportionality, not in the surrounding machinery.
