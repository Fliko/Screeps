## Successes

1. **Walking skeleton delivered cleanly** - 4/4 stories completed, all automated gates pass
2. **Game/Memory adapter pattern established** - Transitioned from brittle `vi.stubGlobal` to typed, injectable adapters
3. **Code review process worked well** - Caught real issues (AC2 test non-functional, measurePhase missing tests)
4. **Systematic patch application** - 8 patches applied across all stories

## Challenges

1. **Testing without local environment** - No local Screeps environment to test against; all testing must be unit tests + sim observation
2. **Brittle mocking with `vi.stubGlobal` and `vi.resetModules()`** - Story 1.4's initial test approach was fragile and non-functional
3. **Tests written after implementation** - Led to testing gaps discovered during code review
4. **Sim verification is manual** - Not automated, not repeatable, easy to skip

## Key Insights

1. **Interface-based testability is foundational** - Without a local Screeps environment, injectable interfaces are how we test. Game/Memory adapters prove this works.
2. **Test-driven design with interfaces prevents gaps** - Define seams first, then implement. Story 1.4's testing issues came from writing tests after implementation.
3. **AD-10 seam enforcement is non-negotiable** - No direct Game/Memory access outside adapter modules. This enables Epic 2's world snapshot.
4. **Code review catches real issues** - 8 patches applied across Epic 1. AC2 test was non-functional until review caught it.
